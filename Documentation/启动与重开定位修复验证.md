# 启动与重开定位修复验证

日期：2026-11-05。

## 原因与修复

原有检查仅要求菜单栏窗口非零尺寸。AppKit 启动期间可能先提供尺寸，再更新窗口位置；位于 `(0,0)` 或屏幕下方的临时窗口同样通过检查，面板随后被屏幕边界限制到左下角。首次启动与运行中重新打开还使用了不同的显示入口，原先只等待窗口附着，未确认位置稳定。

新增模拟原点窗口检查后，旧代码明确复现两处左下角弹窗。最终修复：

- 根据按钮转换到屏幕后的真实矩形，确认它位于某一屏幕顶部菜单栏区域；不以 `window.screen` 或默认屏幕坐标代替有效锚点。
- 连续三个 20 毫秒采样位置一致后再显示；首次启动、退出后重开、运行中再次打开共用此流程。
- 对仍在等待的显示请求使用取消与请求编号保护，用户打开设置或取消面板后，旧请求不能延迟弹出。
- 观察菜单栏按钮和其窗口的位置、尺寸、屏幕变化，重新定位已展开的面板。定位暂时无效时不使用原点或默认屏幕回退。
- 面板顶部同时受菜单栏锚点和屏幕可用区域限制，避免 AppKit 在显示时再次调整窗口位置。
- 处理策略恢复／首次配置提示早于面板加载的情况，在渲染前确保视图已加载。

## 验证范围

| 场景 | 结果 |
| --- | --- |
| 未附着／零高度菜单栏窗口 | 不显示临时面板 |
| 已有尺寸但仍在 `(0,0)` 或屏幕下方 | 修复前复现错误；修复后拒绝显示 |
| 图标稍后移动至菜单栏 | 等待稳定后展开，无临时左下角面板 |
| 首次使用、未配置辅助组件的内容 | 独立模拟状态通过；没有重置真实偏好和授权 |
| 同一面板连续三次延迟锚点重新展开 | 顶部定位通过 |
| 多屏、负屏幕坐标、菜单栏锚点移动 | 模拟几何及位置变化检查通过 |
| 等待中取消显示 | 不会延迟重现 |
| 已安装正式版正常退出后重新启动 | 实际进程退出和重新启动已确认，主面板正常显示 |
| 从访达打开运行中的 `/Applications/Qiming.app` | 主面板再次显示，组件通信正常 |

解锁后最终完整检查：55 项核心隔离测试通过；96 组面板切换、40 组玻璃边缘检查通过，0 处面板回归失败。此前锁屏期间出现的焦点／动画检查失败，已在解锁后重新验证通过。可使用 `zsh Scripts/check_panel_presentation.sh --startup-only` 单独检查启动定位。

首次安装的配置状态通过独立模型覆盖，未进行删除应用偏好、撤销系统通知或辅助组件授权的破坏性重装。多屏覆盖为几何模拟，不表示已连接不同外接屏逐一实测。
