# UI 对齐与液态玻璃

更新日期：2026-11-04。玻璃边缘修正版。已区分外缘留边与内部随模糊半径增加的浅色带，并在相同设置预览背景中完成修改前后对比。

## 当前视觉目标

保留用户认可的 Clear 透镜形变与细亮边；消隐背景小字和细线，保留饱满色块与大轮廓。仅保留“通透度”滑杆，向左更柔化、向右更清晰。底色、色彩补偿、文字和控件的 alpha 均不随滑杆改变。

## 当前代码中的光学合成

`Qiming/UI/GlassSurfaceView.swift` 使用以下顺序：

1. 一层 `NSGlassEffectView`，始终 `.clear`、`tintColor = nil`；内容容器非空，由系统处理透镜形变、边缘折射和高光。
2. 其后的独立 `NSView.backgroundFilters` 背景滤镜通道，使用公开 Core Image `CIDiscBlur` 圆盘散焦。它处理背景，不是对前景视图执行 `contentFilters`。
3. 同一背景通道的固定 `CIColorControls`：saturation 1.14、contrast 1.06、brightness -0.025，用于减轻全局泛白、保留蓝色和橙红色的色彩分离。它不改变色相，也不受滑杆驱动。
4. 前景随应用浅色／深色外观使用深色／浅色文字，取消绘字投影。浅色保持 8% 中性黑色基础处理，深色使用 32% 中性黑色基础处理；文字与控件附近另有轻量、边缘柔化的局部对比支持，空白区与外围透镜保持透明。普通设置表单使用系统语义颜色。

背景滤镜的采样视图与原生透镜保持同级，向四边各扩展 26pt；滤镜输出由独立圆角蒙版裁到面板边缘，仅留下 1 个物理像素的原生高光。取消旧版 3pt 内缩，输入采样范围与输出裁切范围分别处理。当前代码没有叠加 Regular 玻璃、HUD 蒙层或自绘伪折射纹理。浅色前景下的白色对比支持仅限文字与控件附近，不铺满整个面板。

## 滑杆的准确含义

滑杆值 `t` 的范围为 0…1，实际圆盘散焦半径为：

```
r = 24 × (1 - t)^1.2
```

半径量化为 0.05，只有值发生变化时才更新滤镜。每个新半径提交独立的 `CIDiscBlur` 对象，避免可变滤镜对象复用导致渲染结果缓存不刷新。0 对应最强散焦，1 对应取消额外散焦；默认值按用户确认设为 0.75（滑杆的 75% 位置），“恢复默认”同样回到 0.75。不会在清晰原图与固定模糊图之间交叉淡化，因此不刻意保留一份清晰小字作为重影。

这是应用组合公开 AppKit 与 Core Image API 的实现，并不是 Apple 控制中心的完整内部算法，也不声称 `NSGlassEffectView` 公开了自己的散射半径。折射来自系统 Clear 材质，应用调节的是附加的背景散焦。

## 原生背景与兼容性

菜单面板由透明 `NSPanel` 承载；玻璃先采样背景，再由应用背景通道进行散焦。设置预览与带本地图像的 QA 预览使用相同玻璃组件。

窗口内图像背景已观察到 Clear 折射与圆盘散焦可共存，前景清楚。两个独立原生窗口的对比中，左列为 Clear，中、右列为额外圆盘散焦 8／18；用户已直接确认“中、右列逐渐更模糊，背景色彩正常”。单窗口截图工具会移除窗口背后的内容，因此跨窗口光学结果以这次用户的屏幕观察为依据。最终 Debug 完整面板与预览均已检查实时联动；原生 GlassSurfaceView 使用共同 backing 层级，前景不进入背景滤镜链。

macOS 26 以下使用 `NSVisualEffectView.hudWindow` 降级；滑杆调整材质覆盖量，不能提供新玻璃折射或与新实现相同的连续散焦。降低透明度时隐藏光学层并使用实底；增强对比度时光学层局部使用高对比外观，内容底色随应用浅色／深色外观增强；不修改用户系统设置。

没有使用私有 KVC、私有 backdrop 层、屏幕捕获、背景截图替换或第三方渲染库。参考图仅供本地 QA，不打包进应用。

## 可读性优化与恢复（2026-11-03）

本轮遵循“尽量保留液态玻璃效果”：保留单层原生 Clear 透镜、原有色彩补偿、圆盘散焦曲线和 75% 默认位置，不增加 Regular 材质或整面浅色填充。

- 原来整个 `GlassSurfaceView` 强制 darkAqua，现在仅光学材质层保留该外观。前景继承应用／系统外观，浅色使用近黑主文字与深灰说明，深色使用近白主文字与浅灰说明。
- 删除标签 `NSShadow`，避免白色文字的浮雕／描边感。底部链接、计时图标和状态胶囊同时适配外观。
- 文字及按钮下方共享一层局部对比支持，遮罩根据实际控件框生成，边缘柔化 10pt。浅色局部白色强度上限 34%，深色局部近黑上限 30%；实际边缘经柔化更弱。空白区域与玻璃外圈不套阅读底板，避免明显卡片。
- 深色基础中性压暗为 32%，减小浅色网页后方的亮度干扰，同时降低局部深色斑块的强度；浅色基础处理保持原来的 8%。这是固定前景对比处理，与通透度滑杆独立，不改变滑杆的散焦含义。
- 局部遮罩在布局与滚动位置变化时重算；不读取屏幕或背景像素，也不增加后台采样或定时器。遮罩自身的柔化与玻璃背景的圆盘散焦是两件事。

## 启动与策略切换闪动修复（2026-11-03）

复现后定位到两个直接原因：

1. `choose` 先把第二个策略放入 `pending`，再调用同步发布更新的 `clearMessage()`。渲染在 `pending` 清空之前发生，错误地插入“配置辅助组件”卡片，导致面板短暂增高后回落。现先判断是否真的需要确认并一次性确定本地状态，再发布更新。辅助组件已就绪时，第二个策略不再经过确认卡片状态。
2. 默认启动会调用 `showPanel()`；状态栏按钮尚未附着原生窗口、或其原生窗口高度尚为零时，`updateFrame()` 定位失败，却仍 `makeKeyAndOrderFront()`，面板可能显示在屏幕默认原点（左下角）。普通启动现在只显示菜单栏图标，不自动展开；未就绪的定位锚点直接拒绝展示，并禁用面板的系统窗口恢复。

同时处理：确认“始终常亮”后不先按旧策略收缩，再按异步结果展开。请求期间保留窗口高度，结果确定后一次调整；窗口 frame 更新按一轮事件合并、跳过相同 frame，使用非动画方式保持顶部锚定。点击当前策略可取消另一策略的待确认卡片，真实缺失辅助组件时仍展示必要的配置入口。

回归使用 `zsh Scripts/check_panel_presentation.sh`：直接编译实际 PanelController、GlassPopover、玻璃和控件代码，提供隔离模拟 AppModel，不连接 XPC、不修改电源／锁屏／屏保。覆盖三种策略的全部 6 个方向 × 2 个界面方案 × 中英文，共 24 组；另检查无效锚点隐藏、取消待确认策略、缺少组件时保留配置卡片。

修复前复现了无效锚点仍显示窗口，以及第二个策略的瞬时配置卡片。修复后 24 组全部通过：跟随系统 → 第二策略的窗口 resize 事件为 0；进入“始终常亮”只有确认页展开、成功后收起各一次；窗口顶部位置不跳动。原始日志保存于 `Documentation/面板切换回归.log`。

## 灰幕玻璃与模块玻璃

灰幕玻璃在原生 Clear 透镜和背景散焦之上使用连续的中性灰衬底。文字使用白色，辅助说明使用略低亮度的白色。衬底强度与通透度滑杆分开，避免调高通透度时失去文字衬托。

模块玻璃是默认方案。三个内屏策略共用一张圆角灰玻璃卡片，各行以细线分隔，当前策略由蓝色开关标示。会话计时与时长选择共用一张卡片，熄屏、退出和临时提示各自成组。macOS 26 及以上每张卡片有独立的原生 Clear 透镜，浅灰衬底内缩 1pt，露出折射边缘和高光。面板共用背景散焦。设置页提供相应的模块预览。
